Research interests

Evaluating AI-generated code

When a model writes a compute kernel, the interesting question is not whether it compiles but where it loses to a tuned library, by how much, and on which shapes and thread counts. I work on the benchmarking methodology that answers this, and on what the answer implies for how generated code should be reviewed.

Autotuning and performance modelling

Searching tiling, blocking and threading parameters with Bayesian optimisation, gradient descent and annealing, then comparing what each search strategy actually buys on real hardware.

AI agents in the engineering process

An empirical question I meet at work: when analysis, development and testing are partly handed to agents, what measurably changes, and what only appears to.

Research and projects

TrustGate

Quality gate for generated Python
Benchmarked against four static analysers
0.854 recall vs 0.341

A merge gate scoring Python against the defect profile of model-written code: hallucinated imports and APIs, invented keyword arguments, stub implementations, hard-coded filler values. It returns an explainable trust score and a verdict a CI pipeline can act on. The point of the project is the measurement: on a corpus of 245 samples it is compared against bandit, semgrep, ruff and flake8, and on the slice that matters, generated-code defects, it recalls 0.854 against 0.341 for the next best tool, and it raised no false positive on any of the 74 clean files in that corpus.

AI-Driven BLAS Library

Research project (TER), Paris-Saclay
With Rosemarie Streefkerk, supervised by Oguz Kaya
Graded 19/20

The question was whether a single-precision BLAS library, written entirely by a code model under natural-language prompting, can match hand-optimised references on AVX2 and OpenMP hardware. Nineteen kernels across all three levels, benchmarked against OpenBLAS. The answer is yes, on one condition: the human does the hardware diagnosis. Across 36 tasks the model failed 8 times, and almost every failure was mathematically correct code that was pathological on real silicon: column-stride access, false sharing, a sequential reduction where a binary tree was needed. None of them were algorithmic errors, and the model could not diagnose any of them unprompted.

Autotuning the SGEMM block sizes with Bayesian optimisation reached the best result in the fewest trials, 66.92 GF/s in 25 evaluations, and every search strategy beat the default configuration by 10 to 15 percent.
